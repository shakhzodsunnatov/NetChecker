# NetChecker 2.x — удаление MCP и дорожная карта

**Дата:** 2026-08-04
**Статус:** утверждено
**Охват:** релизы 2.0.0, 2.1.0, 2.2.0, 3.0.0

---

## 1. Контекст и проблема

В релизе 1.3.0 (`ab28cd2`, 11 апреля 2026) в SDK был добавлен MCP-сервер — HTTP-сервер внутри приложения, позволяющий AI-инструментам удалённо управлять хостовым приложением. Решение признано неудачным: оно расширяет публичный API на ~4500 строк, добавляет в SDK для отладки трафика сетевой сервер и целый транспортный слой, не относящийся к основной задаче продукта.

MCP удаляется полностью. Освободившееся место занимают функции, которых пользователям действительно не хватает.

### Ключевое ограничение: 1.3.0 нельзя откатить

PR #13 — squash-мёрдж всей долгоживущей ветки `development` в `main`. Помимо MCP в него попала ценная и не связанная с AI работа:

- haptic feedback при shake-жесте;
- структура `NetCheckerConfiguration`;
- фикс видимости тулбара (`NavigationStack` в каждой вкладке);
- персистентность настроек (`MockEngine.isEnabled`, `BreakpointEngine.isEnabled` → `UserDefaults`);
- переключение окружения в экране Edit & Retry;
- «Copy Full API» в меню шаринга и поддержка буфера обмена на macOS;
- фикс брейкпоинтов на ответах (#9), которые до этого не срабатывали вовсе.

`git revert ab28cd2` уничтожил бы всё перечисленное. Удаление обязано быть точечным.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Судьба MCP | Полное удаление из репозитория. Код остаётся доступен в истории git и в теге `1.3.0`. |
| Версия | `2.0.0` — удаление публичного API является ломающим изменением. |
| Git-флоу | `feature/*` → `development` через **squash merge**; `development` → `main` через **merge-коммит**. |
| Теги и релизы | Создаёт вручную владелец репозитория. |
| История коммитов | Не переписывается. Новые коммиты создаются без трейлеров `Co-Authored-By`. |

### Почему `development` → `main` мёрдж-коммитом

Squash-мёрдж фичевой ветки в `development` корректен: одна фича — один коммит. Проблему создал squash *всей ветки* `development` в `main`: двадцать независимых изменений схлопнулись в один неделимый коммит, из-за чего MCP стало невозможно откатить, не потеряв остальное. Мёрдж-коммит на границе `development` → `main` сохраняет пофичевую гранулярность и возможность точечного отката.

**Критерий приёмки:** `grep -ri "mcp" Sources/ Tests/` не даёт совпадений; `swift build` и `swift test` зелёные.

### 3.2 Побочный дефект, устраняемый заодно

В `TrafficInspectorModifier.swift` вкладки MCP и Settings имеют одинаковый `.tag(3)`. Дублирование тегов ломает выбор вкладки при использовании биндинга. После удаления MCP теги перенумеровываются подряд.

### 3.3 Environments — довести до рабочего состояния

Функция публично обещана в README как «Coming Soon» с февраля 2026. Бэкенд полностью готов и покрыт кодом: `EnvironmentStore`, `URLRewriter`, `EnvironmentGroup`, `Environment`, `EnvironmentVariable`. Готовы и четыре экрана: `EnvironmentSwitcherView`, `AddEnvironmentView`, `EditEnvironmentView`, `QuickOverrideView`. Перехватчик уже применяет переписывание URL и подстановку заголовков (`NetCheckerURLProtocol.startLoading`, строки 160–171).

Отключена только вкладка — она закомментирована в `TrafficInspectorModifier.swift` (строки ~250–279).

**Работа:** раскомментировать вкладку, присвоить корректный тег, проверить все четыре экрана на живом устройстве, убрать пометку «Coming Soon» из README.

**Критерий приёмки:** создание группы окружений, переключение между окружениями и quick override с автоистечением работают из UI; трафик уходит на переписанный хост.

## 4. Архитектура вкладок

`TabView` на iOS отображает не более пяти вкладок, далее сваливая остальные в раздел «More». Четыре новые функции в отдельные вкладки не помещаются, поэтому они распределяются по смыслу.

| Функция | Размещение | Обоснование |
|---|---|---|
| Environments | вкладка (пятая) | самостоятельный раздел с несколькими экранами |
| Network Conditions | секция в Settings | глобальный переключатель состояния, а не рабочее место |
| HAR import | кнопка в тулбаре Traffic | разовое действие, логично рядом с экспортом |
| WebSocket | внутри Traffic, отдельным фильтром | тот же трафик, другой транспорт |

Итоговый состав вкладок, начиная с 2.0.0: **Traffic · Environments · Mocks · Breakpoints · Settings**.

## 5. Релиз 2.1.0 — Network Conditions

Симуляция сетевых условий для всего трафика: профили 3G, Edge, DSL, offline; настраиваемые задержка, ограничение полосы и вероятность потери пакетов.

### Блокирующий дефект, который нужно исправить первым

В `NetCheckerURLProtocol.handleMockResponse` (строка 235) задержка мока реализована как `Thread.sleep(forTimeInterval: delay)`. Это **блокирует поток загрузки URL**. Для одиночного мока последствия ограничены, но глобальный троттлинг на такой основе подвесит приложение.

Задержки переводятся на `DispatchQueue.asyncAfter`, что чинит и существующее поведение моков, и открывает дорогу троттлингу.

### Состав

- `NetworkConditionProfile` — предустановленные и пользовательские профили;
- `NetworkConditioner` — применяет задержку, ограничение полосы и потери на уровне `NetCheckerURLProtocol`;
- ограничение полосы реализуется дроблением доставки тела ответа клиенту на порции с расчётными интервалами;
- потери пакетов моделируются вероятностным завершением запроса ошибкой `NSURLErrorNetworkConnectionLost`;
- UI: секция в Settings с выбором профиля и ручными регуляторами;
- персистентность выбранного профиля в `UserDefaults`, по умолчанию выключено.

## 6. Релиз 2.2.0 — HAR import и replay

Загрузка HAR-файла и воспроизведение записанной сессии в виде набора моков — работа приложения в офлайне на реальных данных.

### Состав

- `HARParser` — разбор HAR 1.2. Структуры `HAR`, `HARLog`, `HAREntry` и остальные уже описаны как `Codable` в `HARFormatter.swift`, но объявлены `private`; их видимость повышается до `internal`, добавляется декодирование;
- `HARImporter` — преобразование записей HAR в `TrafficRecord` для просмотра и в `MockRule` для воспроизведения;
- корректная обработка тел в base64 (`content.encoding == "base64"`);
- UI: кнопка импорта в тулбаре Traffic, файловый пикер, экран предпросмотра перед применением;
- совместимость проверяется на экспорте из Chrome DevTools, Safari Web Inspector, Charles и собственного `HARFormatter`.

Обратное преобразование — экспорт — уже существует и не затрагивается.

## 7. Релиз 3.0.0 — WebSocket inspection

Наиболее крупная работа, требующая нового слоя перехвата и новой модели данных. Вынесена в отдельный мажор.

### Почему нельзя переиспользовать текущий перехватчик

`URLSessionWebSocketTask` не проходит через цепочку `URLProtocol` — механизм, на котором построен весь перехват NetChecker, для сокетов недоступен. Существующий `SessionSwizzler` подменяет `protocolClasses` у `URLSessionConfiguration`, что на сокеты не влияет.

### Слой перехвата

Гибридный подход, зеркалящий существующие уровни `InterceptionLevel`:

- **`.full`** — swizzling `URLSession.webSocketTask(with:)`, а также селекторов `sendMessage:completionHandler:` и `receiveMessageWithCompletionHandler:` класса `NSURLSessionWebSocketTask`. Это методы Obj-C, подмена выполняется штатно. Асинхронные Swift-варианты сводятся к этим же реализациям.
- **`.manual`** — публичная обёртка `NetChecker.webSocketTask(with:)` для интеграций, где swizzling нежелателен.

### Модель данных

У сокета нет пары «запрос — ответ»; есть долгоживущее соединение и поток кадров в обе стороны. Поэтому вводятся отдельные типы, а не расширяется `TrafficRecord`:

- `WebSocketRecord` — соединение: URL, состояние, время открытия и закрытия, код закрытия, массив кадров;
- `WebSocketFrame` — кадр: направление, тип (`text` / `binary` / `ping` / `pong` / `close`), полезная нагрузка, размер, временная метка;
- `WebSocketStore` — хранение с ограничением на количество кадров по аналогии с `TrafficStore`.

### UI

- фильтр по транспорту в списке Traffic;
- экран соединения с живой лентой кадров, автопрокруткой и паузой;
- подсветка JSON внутри текстовых кадров через существующий `JSONSyntaxView`;
- экспорт ленты кадров.

### Что осознанно не входит

Моки и брейкпоинты для WebSocket в 3.0.0 не реализуются. Сначала нужен работающий и проверенный на реальных приложениях перехват; вмешательство в поток кадров — предмет отдельного проектирования.

## 9. Риски

| Риск | Смягчение |
|---|---|
| Пользователи 1.3.0, вызывающие `startMCP()`, получат ошибку сборки | Мажорная версия 2.0.0 не подтягивается автоматически по `from:`. В release notes даётся явное указание. |
| Удаление `MCPTests.swift` обрушивает покрытие с 22 тестов до 5 | Раздел 3.5: покрытие восстанавливается в том же релизе, целевой уровень — 40 тестов. |
| Swizzling WebSocket опирается на приватные детали Foundation и может сломаться в новой версии iOS | Уровень `.manual` с явной обёрткой даёт запасной путь, не зависящий от swizzling. |
| Ограничение полосы через дробление доставки — приближение, а не точная эмуляция канала | Заявлять как инструмент отладки, не как измерительный прибор. Документировать честно. |
